## A. What is this file?

A forward-only PostgreSQL migration for desktop push subscription and delivery.

## B. Why does ARKST need it?

It supports desktop push subscription and delivery. A newly assigned student gets an inbox entry; an opted-in browser may also receive a dispatched desktop push.

## C. How does it work?

It changes database objects in version order. Identified objects: table: `push_subscriptions`, `push_deliveries`; function: `register_push_subscription`, `push_subscription_status`, `disable_push_subscription`; index: `push_subscriptions_active_user_idx`, `notification_outbox_due_idx`, `push_deliveries_pending_idx`. The SQL is applied or asserted by the local Supabase CLI. Review the exact DDL/RLS/SQL assertions in the original file. This adds per-user device subscriptions, durable outbox attempts and claim/retry state. The trusted dispatcher reads these records; the browser cannot read another user's endpoint or encryption keys.

## E. What happens if I modify this file?

Changing it after application would make database history disagree with Git. Use a new migration and rerun RLS/integration checks.

## F. How do I verify a safe change?

In the isolated local stack, confirm migration history, then run `npm run test:rls` and `npm run test:local`. Never reset a populated database just to test a migration.

## G. Important cautions

Already-applied migrations are historical records: add a new forward migration. Check RLS, grants, `SECURITY DEFINER` search paths and rollback behavior in a disposable environment.
