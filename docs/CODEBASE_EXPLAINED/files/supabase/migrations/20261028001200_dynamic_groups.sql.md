## A. What is this file?

A forward-only PostgreSQL migration for named student groups and publication snapshots.

## B. Why does ARKST need it?

It supports named student groups and publication snapshots. A placement group is edited without rewriting already published student assignments.

## C. How does it work?

It changes database objects in version order. Identified objects: table: `department_operation_capabilities`, `academic_groups`, `group_membership_history`, `activity_target_groups` (plus 1 more); function: `can_department_operation`, `validate_academic_group`, `guard_group_scope`, `validate_group_membership` (plus 8 more); trigger: `academic_group_validate`, `academic_group_scope_guard`, `group_membership_validate`; index: `unique_department_group_name`, `one_current_group_membership`, `group_membership_history_group`. The SQL is applied or asserted by the local Supabase CLI. Review the exact DDL/RLS/SQL assertions in the original file. Groups and membership changes are stored in PostgreSQL with audit history. Publishing a group Activity snapshots current eligible students into the same `activity_assignments` table, so later edits do not rewrite old work.
